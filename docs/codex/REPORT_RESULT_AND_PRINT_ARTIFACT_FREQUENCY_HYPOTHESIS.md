# Report, Result, and Print Artifact Frequency Hypothesis

## Purpose

This document provides a first-pass hypothesis about which result/report/print artifacts are likely used constantly versus occasionally in the current Tabroom operational model.

This is explicitly an inference from source prominence, menu exposure, and workflow integration. It is not usage telemetry.

## Source Basis

Inputs considered:

- presence in `tabbing/report/index.mhtml`
- dedicated print/report files
- public results navigation prominence
- dependencies from publication, awards, or qualifier flows
- prior codex reporting/results docs

## Frequency Buckets

- `Frequent`
- `Regular`
- `Occasional`
- `Specialized`

## Hypothesis Register

| Artifact / Report Family | Hypothesized Frequency | Basis |
|---|---|---|
| Round results pages | Frequent | Public-facing, core live workflow |
| Final places / standings result sets | Frequent | Core completion and publication path |
| Prelim order / seeding printouts | Regular | Dedicated report path and common operational need |
| Score reports | Regular | Dense operator-facing reporting path |
| Speaker award reports | Regular | Dedicated print/report support |
| Awards ceremony scripts | Regular | Separate ceremony-focused output family |
| Packet reports | Occasional to Regular | Important at some tournaments, but more operationally situational |
| Audit / section audit printouts | Occasional to Regular | High value when needed, not necessarily used continuously |
| Awards pickup views | Occasional | Event-phase-specific operational tool |
| Sweep printouts | Occasional | Ceremony/award-phase oriented |
| TOC / NSDA specialized reports | Specialized | Clearly segment-specific |
| Cume sheets / deep statistical reports | Specialized | Valuable but less universal |
